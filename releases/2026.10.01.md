# Uptimy Agent: open-source, self-hosted uptime monitoring

Most uptime monitors check your services from the outside. That leaves out everything that isn't public: the database behind your API, a worker on a private network, a Deployment that's quietly running on one replica out of three.

**[Uptimy Agent](https://github.com/uptimy/agent)** runs next to your services, inside your Kubernetes cluster, your Railway project or on any server with Docker, and checks them from there. It's one small Go binary with a web UI and a public status page, licensed Apache-2.0. If you've been running Uptime Kuma, it's an alternative that imports your Kuma setup in a few clicks.

```bash
docker run -d --name uptimy-agent -p 8080:8080 -v uptimy-agent:/data ghcr.io/uptimy/agent
```

Open http://localhost:8080 and sign in as `admin` with the password from `docker logs uptimy-agent`.

## What it checks

- **Websites and APIs:** HTTP(S) with status code and keyword checks, TCP, ping, DNS and TLS certificate expiry
- **Databases:** Postgres, MySQL and Redis with a real login and query, not just an open port. Alert when a replica stops being the primary with a query like `SELECT pg_is_in_recovery()`. Works through PgBouncer
- **Kubernetes:** Deployments, StatefulSets and DaemonSets with fewer ready replicas than they should have, using a read-only service account
- **Private hosts:** `postgres.default.svc:5432`, `api.railway.internal` and anything else your services can reach
- **Cron jobs and workers:** heartbeats on an interval or a cron schedule in any time zone, with missed and failed runs, exit codes and how long each run took

Define monitors in the UI, or in YAML from a file, a ConfigMap or an environment variable.

## Alerts, maintenance and a status page

- **Alerts** by email, Slack, Microsoft Teams, Discord, Telegram, ntfy, PagerDuty or webhooks, on down and on recovery, with a failure threshold so a single blip doesn't page anyone. Each channel alerts for every monitor or only the ones you pick
- **Maintenance windows** keep planned work quiet. A monitor that's still down when the window ends alerts then
- **A public status page** at `/status` with your logo, accent color, sections and public names for each monitor. It never shows internal hostnames

## Switching from Uptime Kuma

Upload Kuma's `kuma.db` under **Settings → Import from Uptime Kuma**. You'll see what each monitor and notification becomes before anything is imported. HTTP, keyword, TCP, ping, DNS, TLS, database and push monitors carry over with their intervals, retries, headers and auth, along with your notification channels, which monitors alert where, and what was on your status page. Anything that can't be carried over is listed with the reason.

## Works with Uptimy

The agent works on its own and stays free. Connect it to [Uptimy](https://www.upti.my/?utm_source=github&utm_medium=release&utm_campaign=agent-launch) for the two things a self-hosted monitor can't do alone:

- **Watch the watcher.** If the agent, its node or the whole cluster goes down, nothing is left to tell you. Click **Connect to Uptimy** and the agent checks in with an Uptimy heartbeat every minute; when it goes quiet, Uptimy alerts you from outside. The agent gets a key that can only manage its own heartbeat.
- **Turn alerts into incidents.** New today: connect **Uptimy Agent** under **Settings → Integrations** in Uptimy and paste its webhook URL into the agent's new **Uptimy** alert channel. Down and recovery alerts then open and resolve incidents in your workspace, alongside your other monitors, and can trigger [workflows](https://www.upti.my/workflow-monitoring?utm_source=github&utm_medium=release&utm_campaign=agent-launch): page on-call, post to Slack, open a GitHub issue, or restart a Railway service.

## Get started

**Docker:** the command above, or [`docker-compose.yml`](https://github.com/uptimy/agent/blob/main/docker-compose.yml).

**Kubernetes (Helm):**

```bash
git clone https://github.com/uptimy/agent
helm install uptimy-agent ./agent/deploy/helm/uptimy-agent -n monitoring --create-namespace
```

**Railway:** deploy from the repo and add a volume at `/data`. See [`deploy/railway.md`](https://github.com/uptimy/agent/blob/main/deploy/railway.md).
